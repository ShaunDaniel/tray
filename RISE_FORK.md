# RisePrint — Rise fork of QZ Tray

RisePrint is a Rise-branded fork of [QZ Tray](https://github.com/qzind/tray) that
bakes the **Rise Root CA** into the install so our web app's signed print requests
are trusted with **no Allow/Block prompt** — replacing the manual `override.crt` copy.

## Fork point

- **Upstream:** `qzind/tray`
- **Pinned tag:** `v2.2.6`
- **Branch:** `rise/branding`

Rebase future QZ security releases onto this branch; do not track `master`.

## How trust works (unchanged from upstream's design)

The web frontend presents the leaf cert `*.getrise.in` (`qz.security.setCertificatePromise`)
and signs requests server-side at `POST /v1/sign` (`qz.security.setSignaturePromise`).
The leaf chains to the Rise Root CA, so QZ trusts it once the root is a trusted root.

We install that root via QZ's built-in provisioning. The `ca` step
(`CaInvoker`) writes `rise-root-ca.crt` into the app dir and appends its path to the
`authcert.override` property — **the exact same trusted-root mechanism `override.crt`
uses today** (consumed at runtime by `qz.auth.Certificate`). Because `CaInvoker`
*appends* to `authcert.override`, an ops-supplied `override.crt` still works as a
fallback — that code path is untouched. No private key is bundled; signing stays
server-side.

## Build

Requires **Apache Ant + NSIS (makensis)**; **JDK 17** present. The build bakes the
provisioning in at build time:

```bash
ant -Dprovision.file=provision/provision.json nsis
```

Two optional flags make the build robust on a fresh machine:
- `-Dnsisbin="C:\Program Files (x86)\NSIS\makensis.exe"` — point Ant at NSIS if it
  can't auto-locate it (the `ProgramFiles(x86)` env var is invisible under git-bash).
- `-Djlink.java.target=<local JDK 11.0.x home>` — bundle a **local** JDK 11 (with
  `jmods`) instead of downloading BellSoft's at build time. Avoids the flaky 190 MB
  download; the JDK major must match `jlink.java.version` (11).

Output lands in `./out/`. Rename to `RisePrint-2.2.6-setup.exe`. Verify silent
install: `RisePrint-2.2.6-setup.exe /S`.

### Code signing (do this)
With a `.pfx` Authenticode cert, sign the installer **and** the bundled `.exe`s:

```bash
signtool sign /fd SHA256 /f rise-codesign.pfx /p <PASS> /tr http://timestamp.digicert.com /td SHA256 RisePrint-2.2.6-setup.exe
```

Unsigned → "Unknown publisher" SmartScreen warning for restaurant staff.

## Rebase notes

- Diff is intentionally tiny (2 text files, 14 lines) + regenerated binary icons +
  the new `provision/` dir. Branding+provisioning only, no refactors → QZ security
  patches rebase cleanly.
- Re-run `gen_icons.py` if upstream changes icon dimensions.
- The provisioning CA mechanism (`CaInvoker` / `authcert.override`) is upstream's
  own API; low rebase risk.

## Deliberate deviations / follow-ups

- **`project.datadir` left as `qz`** — internal shared-data folder name, not
  user-visible; rebranding risks path logic for zero benefit. (`PROPS_FILE` *was*
  realigned to `riseprint`: it must equal `project.filename`, or the launcher
  shortcuts + registry icon reference a `qz-tray.exe` that no longer exists.)
- **`VERSION_CHECK_URL` / `VERSION_DOWNLOAD_URL` still point at `qzind/tray`** — left
  functional per spec. A rebranded build will offer "QZ Tray" updates; point these at
  a Rise releases endpoint (or disable the notifier) when one exists.
- **`ABOUT_*_URL` derive from `getrise.in`** (`/licensing`, `/support`, `/privacy`,
  `/download`) — these pages may 404 until created.
- **macOS/Linux:** the `.svg` sources and `apple-icon.icns` are swapped to the Rise
  tile, but those platforms aren't built here. For pixel-perfect native icon sets,
  run `assets/branding/create_branding.sh` (needs ImageMagick + rsvg-convert).
